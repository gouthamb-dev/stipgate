# Benchmark results

All runs on 2026-10-22 against the deployed stack (`deploy/aws/`): Strands Decider 2B
(`StrandsAgents/strands-decider-2B-qwen3.5-v1-2610`, community int8 CPU runtime, 2 vCPU `m7i-flex.large`) and
Amazon Nova Lite (`amazon.nova-lite-v1:0`, us-east-1). Documents are the seeded synthetic held-out set from
`benchmark.py` (seed `20261019`, 100 documents: 45 compliant, 55 not).

## Headline: StipGate vs an LLM-only judge

| Judge | Accuracy | Hallucinated approvals | False halts | Decision tokens (100 docs) | Decision latency p50 / p95 |
|---|---|---|---|---|---|
| **StipGate**: Decider 2B (type + yes/no checks) + date rule | **100%** | **0 / 55** | **0 / 45** | **0** (local model) | 4.7 s / 6.5 s (CPU) |
| Nova Lite, full rubric (same question, options, checks and date rule in words) | 69% | 31 / 55 (56%) | 0 / 45 | 45,922 (~$0.0030) | 0.35 s / 0.46 s |
| Nova Lite, document-type question only | 71% | 29 / 55 (53%) | 0 / 45 | 36,191 (~$0.0025) | 0.34 s / 0.47 s |
| v1 StipGate: type question only, threshold 0.88 | 69% | 21 / 55 (38%) | 10 / 45 (22%) | 0 | 2.7 s / 3.8 s (CPU) |

Per category (documents approved / total):

| Category | Should | StipGate | Nova Lite full rubric |
|---|---|---|---|
| valid paystub | approve | 25 / 25 | 25 / 25 |
| valid two-year W-2s | approve | 20 / 20 | 20 / 20 |
| stale paystub (45-150 days old) | halt | 0 / 12 | **12 / 12** |
| paystub missing employer + YTD | halt | 0 / 8 | **8 / 8** |
| single-year W-2 | halt | 0 / 8 | 0 / 8 |
| corrupted / truncated OCR | halt | 0 / 12 | **11 / 12** |
| utility bill under an income code | halt | 0 / 10 | 0 / 10 |
| bank statement under an income code | halt | 0 / 5 | 0 / 5 |

What it shows:

- Nova Lite was told the 30-day rule and today's date and still approved every stale paystub, every paystub
  missing the employer and YTD, and 11 of 12 garbled scans. Its errors are all on the dangerous side.
- StipGate splits the work: Decider 2B judges *what the document is* and *whether required content is
  there*; plain code does the date arithmetic. Each part does what it is good at.
- On this CPU box the gate is slower than a Nova Lite call. The upstream figure is ~115 ms median per
  question on an RTX 3090 ([inference.md](https://github.com/strands-labs/strands-decider/blob/main/docs/inference.md)),
  so a GPU host is the way to a real-time gate. The win here is correctness, zero decision tokens, and no
  document text leaving the host before the gate.
- Extraction: all 45 approved documents were extracted by Nova Lite (no fallbacks).

## How the thresholds were chosen

`2026-10-22-tuning-seed-4242-raw-scores.txt` holds raw Decider scores on a **different** seed (4242), with no
thresholds applied. On it, valid documents scored 0.84-0.97 on the document-type question and >= 0.91 on
the requirement checks; failing documents scored <= 0.46 and <= 0.75. That set the defaults:
`DEFAULT_CONFIDENCE_THRESHOLD = 0.80`, `DEFAULT_CHECK_THRESHOLD = 0.85`. The 0.88 used in v1 would have
halted 8 of 45 valid documents on the tuning seed.

Honest caveats:

- The set is synthetic and generated by this repo. Real borrower documents are messier.
- The requirement-check wording was written after seeing which held-out categories the v1 gate missed
  (stale, missing fields, single-year W-2), and a few held-out documents were used while probing wordings.
  Thresholds were tuned only on seed 4242.
- One run per configuration. The int8 runtime shows small run-to-run variation (about ±0.02).

## Reproduce

```bash
# StipGate against a live Decider (+ Nova Lite extraction with AWS credentials)
STIPGATE_DECIDER_TIMEOUT_S=60 python benchmark.py --heldout --decider-mode server \
  --decider-url http://127.0.0.1:8099/v1/systemone --json-out stipgate.json

# LLM-only baseline: Nova Lite answers the same rubric (AWS credentials, us-east-1)
python benchmark.py --heldout --llm-judge --json-out nova-judge.json
```

Documents are generated relative to today's date, so dates (not categories) shift between days.
